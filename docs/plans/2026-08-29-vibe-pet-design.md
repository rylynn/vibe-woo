# Vibe Pet 设计文档

日期：2026-08-29
状态：设计已确认，待实施

## 1. 产品定义

一只常驻桌面的像素宠物，在 vibe coding 期间提供低打扰的陪伴、轻量记录和小圈子社交。

**定位**：自己 + 身边朋友使用。零运维成本，无账号体系。

**气质要求**：简单、无负担、cool。任何让用户觉得「烦」或「重」的设计，一律砍掉。

## 2. 已确认的关键决策

| 决策项 | 结论 |
|---|---|
| 技术栈 | Tauri 2 + React/Canvas |
| 平台 | macOS 优先，Windows 跟进 |
| 桌面存在方式 | 全屏透明置顶层 + 动态鼠标穿透 |
| 视觉风格 | 48/64px 像素骨架 + 现代后处理（bloom、CRT 扫描线、呼吸缩放、拖影） |
| 状态感知（MVP） | 前台应用分类 + 键盘活跃度 |
| 宠物人格 | 三档可配（安静 / 偶尔吐槽 / 唠唠），默认安静 |
| 社交载体 | Cloudflare Workers + KV，30 秒轮询 |
| 记事落点 | 本地 Markdown（Obsidian vault 目录），默认方案 |
| API key 存储 | 明文本地配置文件，UI 展示掩码 |

## 3. 架构

```
┌─ Rust 核心（常驻，无 UI） ────────────────────┐
│  WindowMgr    全屏透明置顶窗 + 动态穿透        │
│  Sensor       前台应用 + 键盘空闲秒数（轮询）  │
│  CursorTrack  全局鼠标坐标（60ms 轮询）        │
│  StateMachine 传感器信号 → 宠物状态            │
│  Store        SQLite：配置 / 记事 / 好友        │
│  LlmClient    OpenAI 兼容协议（统一出口）      │
│  Tray         托盘菜单                          │
└──────────────┬────────────────────────────────┘
               │ Tauri IPC (event / invoke)
┌──────────────▼────────────────────────────────┐
│  WebView（透明背景）                            │
│  Renderer   Canvas：像素精灵 + 后处理           │
│  Behavior   漫游 / 待机动作 / 重力 / 情绪       │
│  Overlay    气泡 / 速记窗 / 设置面板            │
└───────────────────────────────────────────────┘
```

### 3.1 鼠标命中判定

**macOS 与 Windows 都必须由 Rust 显式控制穿透。**

> 修订记录：本节曾一度改为「依赖 macOS 的 alpha=0 像素自动透传点击」，
> 实测该方案**完全不可行**，已回退。原因：WKWebView 铺满整个窗口，
> 其 hit-test 只看 DOM 元素矩形，不看绘制内容的 alpha。canvas 铺满全屏
> 就会吞掉所有点击，与是否透明无关。该错误导致整个桌面点击被拦截。

实现方式：

1. 前端每 50ms 上报宠物包围盒 + 拖动锁定标志（同时充当心跳）
2. Rust 每 60ms 轮询光标位置，本地判定命中
3. 命中 → `set_ignore_cursor_events(false)` 接管鼠标；否则恢复穿透

坐标换算：光标与窗口位置是物理像素，包围盒是 CSS 像素，需按 `scale_factor` 统一。

**拖动锁定**：快速拖动时光标会甩出包围盒，若此刻恢复穿透，`pointermove` 丢失，宠物会「脱手」黏在半路。因此拖动期间强制保持接管。

### 3.1.1 穿透的 fail-safe 三原则（安全红线）

全屏透明置顶窗一旦拦截了不该拦截的点击，用户会连托盘都点不到。曾因此发生「只能重启电脑」的事故。因此：

1. **初始即穿透** —— 窗口显示前就 `set_ignore_cursor_events(true)`，任何未知状态都倾向于不拦截
2. **前端失联强制穿透** —— 超过 1.5 秒没收到上报即视为前端崩溃，无条件恢复穿透。**此规则优先级高于拖动锁定**，否则前端在拖动中崩溃会导致永久锁死
3. **仅在明确命中时接管** —— 判定链路上任何一步取不到数据，都按穿透处理

### 3.1.2 退出通道必须冗余（安全红线）

宠物窗口 `closable: false`、不在 Dock、不在 Cmd+Tab。**任何单一退出入口都不可接受。**

现有四重保障：

| 通道 | 依赖 | 验证状态 |
|---|---|---|
| 托盘菜单 | 托盘图标可见 | 需人工确认 |
| 全局快捷键 `Ctrl+Alt+Cmd+Q` | 快捷键注册成功 | 需人工确认（自动化受辅助功能权限限制） |
| `pnpm stop` | 仅需终端 | **已实测可靠** |
| 前端失联自动穿透 | Rust 线程存活 | 已实现 |

托盘图标必须随包内置（`include_bytes!`），不依赖运行时资源解析，且拿不到图标时直接报错而非静默降级。

### 3.1.3 单实例锁（安全红线）

多开会叠加多层全屏透明窗，点击行为无法预测，且视觉上表现为「宠物在多处显示」。必须用 `tauri-plugin-single-instance` 阻止。已实测第二个实例会立即退出。

### 3.1.4 辉光用 dithering（美术选择，非技术强制）

辉光采用棋盘点阵（每像素 alpha 只有 0 或 1），不用 `shadowBlur` / CSS bloom。

**理由已经变化，如实记录**：原先认为这是技术强制 —— 因为「alpha=0 才穿透」，半透明光晕会形成挡鼠标的隐形墙。随着穿透改由 Rust 按包围盒控制，辉光位于包围盒之外，无论 alpha 多少都会穿透，**隐形墙问题不再存在**。

保留 dithering 的现有理由：

1. 点阵发光是像素艺术的传统手法，比高斯模糊更贴合美术风格
2. 纯 `fillRect` 拼点阵比 `shadowBlur` 便宜得多，有利于 CPU 预算
3. 可点区域（身体包围盒）与视觉边界（含辉光）分离是好事：宠物看起来更大更有存在感，但不会误吞用户点击

代码中的 alpha=1 断言测试保留 —— 它现在守护的是美术一致性与性能预算，而非穿透正确性。

### 3.2 零系统权限（P1）

| 信号 | macOS API | 是否需要授权 |
|---|---|---|
| 键盘活跃度 | `CGEventSource.secondsSinceLastEventType` | 否 |
| 前台应用 | `NSWorkspace.frontmostApplication` | 否 |
| 鼠标位置 | `NSEvent.mouseLocation` | 否 |

键盘只取「距上次按键几秒」，**不接触任何键位内容**。装上即用，无授权弹窗。

### 3.3 macOS 窗口配方

基于 `tauri-nspanel`（v2.1 分支）的 `to_panel::<PetPanel>()`，参考生产项目验证过的组合：

| 项 | 取值 | 作用 |
|---|---|---|
| level | `PanelLevel::Dock`（20） | Dock level + nonactivating 才会被 AppKit 路由进全屏辅助层 |
| styleMask | `nonactivating_panel` | **点宠物不抢走编辑器焦点**（体验生死线） |
| collectionBehavior | `stationary \| can_join_all_spaces \| full_screen_auxiliary` | 跟随所有 Space，可浮在全屏应用上 |
| `hidesOnDeactivate` | `false`（**必须显式设置**） | nonactivating 只管焦点，不管 resign-active 时的自动隐藏；不设会出现「点一下宠物它才回来」的延迟 |
| 激活策略 | `ActivationPolicy::Accessory` | 不出现在 Dock 与 Cmd+Tab（替代 `LSUIElement`，dev/prod 均生效） |
| `acceptFirstMouse` | `true` | 第一次点击即生效，无需先激活窗口 |

**两个必须防的崩溃：**

- `setAutorecalculatesTouchBar: false` —— `to_panel()` 的换类操作发生在 Touch Bar finder 已对原 NSWindow 注册 KVO 之后，后续注销时会抛 `NSRangeException`
- 全部 panel 配置包在 `objc2::exception::catch(AssertUnwindSafe(...))` 内 —— `msg_send!` 遇 Obj-C 异常会 panic，兜底后最坏只是退化为普通 NSWindow，不会 SIGABRT

**依赖注意**：`objc2` 必须使用 `tauri_nspanel` 再导出的那一份。直接依赖 `objc2` 会因 `Message` trait 跨大版本不兼容而编译失败。

## 4. 状态机

两个正交维度相乘，避免扁平状态列表互相冲突：

| 维度 | 取值 | 来源 |
|---|---|---|
| 在干什么 | CODING / BROWSING / OTHER / AWAY | 前台应用 bundle id 分类（可自定义规则） |
| 什么节奏 | FLOW / NORMAL / STUCK / RESTING | 键盘空闲秒数 + 连续活跃时长 |

叠加时间修饰符 `LATE_NIGHT`。

### 4.1 核心差异点

**`CODING × STUCK`**：前台是编辑器 + 键盘静默 > 90 秒 → 你在思考或在等 AI 跑完。这是 vibe coding 场景独有信号。
表现：停下自己的事，转向屏幕，跟你一起盯着，偶尔挠头。

**律动同步打字节奏**：FLOW 状态下宠物呼吸/摇摆频率跟实际击键频率挂钩。成本近零，是留存的最大来源。

### 4.2 状态映射

| 状态 | 表现 |
|---|---|
| CODING × FLOW | 精神，律动跟随打字节奏 |
| CODING × STUCK | 停下，转向屏幕，陪你盯着，偶尔挠头 |
| IDLE 2–10min | 自娱自乐：漫游、原地打转 |
| AWAY > 10min | 睡觉，冒 zzz |
| BROWSING | 趴下放松 |
| LATE_NIGHT | 加黑眼圈，律动放缓 |

**原则**：状态只影响宠物「做什么」，不影响宠物「是否打扰你」。安静型人格下所有状态均无文字。

### 4.3 动作资源

每个形象一套，共 8 组，每组 2–6 帧：

```
idle / walk / sit / sleep / peek / celebrate / poke_react / drag
```

一张 spritesheet + 一份 JSON（帧序、时长、锚点）。这是「换形象」的标准接口。

**活跃度滑块**控制：漫游频率、自发动作频率、动画幅度。最低档退化为静态挂件。

### 4.4 呼吸必须靠帧动画，不能靠代码缩放（M3 硬约束）

M1 用纯色方块时，呼吸是用 `Math.round(side * scale)` 做的连续缩放。代码审查实测发现：该做法下**约 95% 的帧渲染边长不是基础格的整数倍**（3x 档位下在 2.875–3.125 倍之间连续变化）。

纯色 `fillRect` 看不出问题，所以这在 M1 是安全的。但一旦换成 `drawImage(spriteSheet, ...)`，每帧重采样会让精灵持续抖动 —— 等于把 5.2 节「牺牲滑块自由度换质感」付出的代价又退了回去。

**因此 M3 引入精灵图时必须**：

- 废弃代码缩放呼吸
- 呼吸交给美术：在 `idle` 动画的 2–4 帧里让身体高度差 1–2 个艺术像素
- 代码只负责按整数倍放大播放，永不做非整数缩放

### 4.5 交互不得写回状态（已在 M1 修正）

交互期间（拖动、点击反馈）需要临时提到 30fps，但**不能把 activity 写回状态字段**。否则拖一下睡着的宠物，松手后它会「忘记」自己本该在睡觉 —— 接入自动状态感知后，表现为「摸一下宠物，它就忘了你其实已经离开了」。

实现方式：用派生方法在渲染时临时提档，状态字段只由传感器和用户设置写入。

## 5. 交互与性能

### 5.1 P1 交互

- 单击 poke（连点会被烦到）
- 拖动 + 松手掉落
- 右键菜单
- 全局快捷键呼出速记窗（P1 留入口，P2 实现）

### 5.2 三个易翻车点

**尺寸必须是整数倍档位**。像素艺术经非整数倍缩放必糊。渲染用 `nearest-neighbor` + `image-rendering: pixelated`，尺寸档位 `1x/2x/3x/4x`（48/96/144/192px），默认 2x。牺牲滑块自由度换质感。

**自适应帧率**。睡眠态 4fps、待机态 12fps、FLOW/交互态 30fps，完全无动画时停掉 `rAF`。

**性能验收指标（硬性）**：
- 空闲 CPU < 1%
- 活跃 CPU < 3%
- 常驻内存 < 100MB

做不到即视为失败，功能全做完也不算通过。

### 5.2.1 CPU 超标问题（M1 未解决，遗留至 M2）

**实测现状**（release 构建、待机、96px 宠物、稳定 20 秒后取瞬时值）：

| 进程 | CPU | 内存 |
|---|---|---|
| vibe-pet 主进程 | ~4.6% | 73MB |
| WebKit WebContent | ~4.7% | 35MB |
| WebKit GPU | ~2.7% | 26MB |
| **合计** | **约 9–12%** | 约 134MB |

内存也超标（134MB vs 目标 100MB），但主要来自 WebKit 三进程架构，属 Tauri 固有成本。

**已排除的假设（均经实测否定，不要重复调查）**：

1. ~~dither 辉光的 fillRect 太多~~ —— 实测仅 93 次/帧，量级不足以解释
2. ~~每帧全屏 clearRect~~ —— 已改为脏矩形清除，CPU 无改善
3. ~~IPC 上报过频~~ —— 上报间隔从 50ms 放宽到 1000ms（降低 20 倍），CPU 几乎不变

**尚未验证的方向（M2 优先调查）**：

- **透明全屏窗口的合成成本 —— 当前最可疑**。1440×900 的透明置顶层可能强制 macOS 走离屏合成路径，与画什么、画多少无关。它能同时解释主进程与 GPU 进程的占用。
  验证方法：把窗口缩到 200×200，看 CPU 是否显著下降。
  **若成立，说明「全屏透明层」这一架构选择本身有固定成本**，需重新评估是否改回「跟随小窗口」方案（见第 6 问选项二）。这将是架构级决策，需与用户讨论。
- **Rust 侧 60ms 轮询中的窗口 API 调用**。`cursor_position()` / `outer_position()` / `scale_factor()` 可能每次都跨进程查询窗口服务器。
  验证方法：缓存后两者（窗口不动时不变），只轮询光标。
- **`rAF` 在透明置顶窗口中的真实触发频率**。可能并未按帧率预算降频。
  验证方法：在渲染循环内统计真实 FPS 并打日志。

**当前状态**：功能可用，但不满足「无负担常驻」的产品定位。

**决策（2026-08-29，用户确认）**：接受现状，**不阻塞 M2**。CPU 作为已知问题挂起，理由是用户实机体感可接受。

但保留一条警戒线：这个数字会随动画和精灵图的引入**只涨不跌**。若 M3 之后升到 15% 以上，必须回来处理，且那时动架构的成本会显著更高。上面「尚未验证的方向」保持有效，随时可捡起。

### 5.3 配置面板

- 尺寸档位、活跃度滑块、形象切换（内置 2–3 套 + 导入）
- 人格三档，默认安静
- LLM：`base_url` + `api_key` + `model`（OpenAI 兼容，一套字段通吃 OpenAI / DeepSeek / Kimi / Ollama）
- 应用分类规则（可编辑）
- 开机自启、显示器选择
- 隐身开关（P3）

### 5.4 亲密度

P1 即开始记录：`f(陪伴时长, 互动次数, 被无视次数)`。

- P1 用途：微调宠物亲近程度（高亲密度会主动走向鼠标）
- P3 用途：直接复用为「好友度」数值底座

## 6. P2 记事

### 6.1 核心可靠性原则

**记录必须无条件先落盘，LLM 整理是异步增强。** 断网、key 过期、余额不足都不能导致记不下来。

### 6.2 Obsidian 走文件系统，不走 API

Obsidian vault 就是普通本地 Markdown 文件夹。设置里选一个目录，按 `YYYY-MM-DD.md` 追加写入即可。零 API、零 token、零授权、断网可用。**这是记事的默认落点。**

Notion 需要 API token + database schema，放 P4。

### 6.3 流程

1. 全局快捷键（如 `⌥Space`）呼出极简单行输入条，回车即走，Esc 取消
2. 立即写入 SQLite + 追加当日 Markdown（带时间戳）
3. **异步**交给 LLM：判断 TODO / 想法 / 待查，抽 1–2 个标签，必要时补上下文，结果回填 Markdown
4. LLM 失败 → 静默保留原文，不弹错误

### 6.4 宠物的角色（仪式感）

呼出输入条时宠物走过来凑近看；回车后点头，把内容「收进包裹」。让记事从操作变成互动。

### 6.5 明确不做

不做搜索、不做编辑、不做看板。那些交给 Obsidian。我们只负责「捕获」。

## 7. P3 社交

### 7.1 载体

Cloudflare Workers + KV。免费额度支撑几十人，零运维，服务端约 100 行（上报状态 / 拉好友状态 / 投递事件三个接口）。

**不用 WebSocket，30 秒轮询**。上下线无需毫秒级精度，省电且省一半复杂度。

### 7.2 身份

无账号体系。本地生成 `pet_id` + 6 位邀请码，互换即成好友。无邮箱、无密码、无登录。

### 7.3 隐私红线（写死在代码里，不做成可放宽配置）

| 上报 | 绝不上报 |
|---|---|
| `CODING` / `IDLE` / `AWAY` / `OFFLINE` | 应用名、窗口标题 |
| 昵称、形象 id、好友度 | 项目名、文件名、代码内容 |
| 最后活跃时间 | 击键内容、任何截屏 |

另需**隐身开关**：用户有权不让人看见自己凌晨在写代码。

### 7.4 串门机制（全异步）

1. 好友度到阈值 → 宠物自己决定出门，上报 `visit` 事件
2. 对方端轮询拿到 → 你的宠物出现在他桌面，飘「XX 来串门了」
3. 他点击互动 → 上报 `interaction` 事件
4. 你下次轮询拿到 → 宠物回家后表现「我被摸了三下」，好友度 +

**双方无需同时在线，无需任何确认**。天然不打扰。

## 8. P4 图片转像素风

### 8.1 不做「生成全新精灵」

宠物有 20+ 帧。生图模型逐帧生成时，形体/配色/朝向必然漂移，动起来会抖。这是 AI 生成精灵图方案的死穴，非提示词可解。

### 8.2 做「提取特征 → 套用骨架」

1. 算法提取**主色板**（K-means 取 4–6 色，纯本地、零成本、稳定）
2. 多模态模型只输出**特征标签**（如「橘猫 / 长耳 / 戴眼镜」）
3. 色板重映射到现成骨架，按标签挂 1–2 个配件（耳型、头顶物）

牺牲「完全复刻」，换来配色神似 + 动作丝滑。

## 9. 里程碑

| | 内容 | 验收 |
|---|---|---|
| M1 | 透明置顶窗 + 会呼吸的像素方块 + 拖动 + 点击 | 不抢编辑器焦点、多屏正常、空闲 CPU < 1% |
| M2 | 状态感知接通（含 `CODING×STUCK`、律动同步） | 切编辑器/发呆/离开，动作正确切换 |
| M3 | 完整宠物：8 组动作、漫游、重力、托盘设置、换形象 | 日常可常驻 |
| M4 | 速记 + Obsidian 落盘 + LLM 异步整理 | 断网仍能记 |
| M5 | 好友状态 + 串门 | 两台机器互见 |
| M6 | 语音输入、图片转像素、Notion | — |

**M1 故意做得很小，但一次性验证全部硬技术风险**：透明窗口、动态穿透、不抢焦点、低 CPU。四条中任一条不通过，方案就得改 —— 必须在画任何一帧美术之前知道答案。
