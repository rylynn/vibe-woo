# 在线总览 / 串门近距离互动 / 通知气泡收拢 · 设计文档

日期：2026-09-20
状态：已与用户逐节确认

## 背景与摸底结论

用户反馈三个问题，摸底调查结论：

1. **「今日在线」常年空白**：`/online/random` 三层字段结构（前端 `OnlineRow` / Rust `OnlineUser` / 服务端 `users[]`）完全一致，无解析错配；空列表来自服务端过滤链——`onlineRandom()` **按设计排除自己与所有好友**（`lib-account.js:965`），候选人还需 8 分钟内心跳过且未隐身。「今日在线」实为「陌生人推荐」，与下方好友列表按构造互斥；小用户基数下合法为空。问题是区块名与用户预期（「今天谁在线」）错位。
2. **串门交互不清楚、容易忽略**：访客宠物落在屏幕固定槽位（28%/50%/72% 宽、72% 高），与主宠物无近距离互动；访客身体刻意不可点（原设计「摸访客」interaction 链路是死代码：服务端无 endpoint、前端无点击路径）；出门方零反馈（宠物瞬间 clearRect 消失、被拒只写日志）；前端不消费 `leave` 事件（访客离开无通知）；自家宠物出门后访客赖着不走（`onAwayChange` 只清快闪层）。
3. **通知类弹窗位置不合理**：主气泡/访客气泡/插件卡锚宠物头顶，但简单通知 Banner、好友回执卡固定右上角；Banner 与主气泡互不知晓，同锚点会重叠；无统一通知队列。

## 已确认的关键决策

| 决策点 | 结论 |
|---|---|
| 今日在线语义 | 改为**含好友的在线总览**：好友（带「好友」徽标、无操作按钮）+ 陌生人（可打招呼）混合 |
| 数据合并方式 | **服务端合并**：`onlineRandom()` 单接口返回混合列表，行加 `is_friend` 字段；前端单接口渲染，心跳链路不动 |
| 串门互动形态 | **自动演出 + 可点击**：对话/动作编排加强，访客身体可点（激活 interaction 死代码链路） |
| 近距离方式 | **伙伴式跟随**：访客进场走到主宠物身旁，之后保持距离跟随其游走；对话拍短暂停步面对面；主宠物游走性不牺牲 |
| 摸摸规则 | 单次串门**限 3 下**（服务端计数权威 + 本地先行拦截），超出访客气泡「摸够啦」 |
| 气泡收拢范围 | 轻通知收拢：简单 Banner + 好友回执卡锚宠物头顶（不在家退回右上角）；**提醒大卡片不动**（可点可拖，刻意不乱跑） |
| 多通知并发 | 不做队列，维持「后来者覆盖」（回执卡 60s 自动收起），YAGNI |

## 服务端设计（lib-account.js，两套部署共用真源）

### 在线总览（onlineRandom 改造）

- 过滤链在现有陌生人管线外**同步收集在线好友**：`mine` 集合中心跳 8 分钟内、未隐身者。
- 响应行新增 `is_friend: true/false`（增量字段，旧客户端 serde 忽略，协议不破坏）。
- 排序：好友在前（按关系亲密度 `aff` 降序，**封顶 3 个**），陌生人在后（维持 seeded 洗牌凑 3~5，继续排除好友与自己）。

### 摸摸（新 endpoint `POST /visit/interact`）

- `requireAuth` 鉴权；`{target}` 必须是**当前在我家 `visitors_<me>` 名单里**且未过期的访客，否则 `not_visitor`（防匿名遍历：只能摸自己家的客人）。
- 计数落在访客条目上：`visitors_<me>` 条目 `{uid, nick, pet_name, at}` → 增加 `pats` 计数；`pats >= 3` 返回 `enough`。
- 每次成功：`pats += 1`、双方关系亲密度 +1（`addAffinity`）、向宠物主人推事件 `interacted`（payload 白名单 `{from, nick, pet_name, count}`，`count` 为本次串门累计值；512B/条约束内）。
- 串门条目 15 分钟过期（`VISIT_EXPIRE_MS`）后自然不可再摸，无需清理任务。

### 事件

- 新事件类型 `interacted`（推给出门方）；`leave` 事件服务端已有，**服务端零改动**，只补客户端消费。

## Rust 侧设计

### 命令层（socialcmd.rs / syncclient.rs）

- `OnlineUser` 增加 `is_friend: bool`（`serde(default)`，兼容旧服务端不回该字段的窗口期）。
- 新命令 `visitor_interact {uid}` → `POST /visit/interact`（`post_authed`）；错误直传服务端中文文案，网络失败本地兜底。

### 同步循环（socialdrive.rs）

- `/visit` 被拒（对方离线/满员/隐身）时不再只写日志：转发 `pet://social` 载荷 `{type: "visit_rejected", nick, pet_name}`，前端一句话提示。
- `interacted` 事件 → `pet://social` 载荷 `{type: "interacted", count, nick}`（补全现有半截死代码分支）。
- `leave` 事件转发已存在，不动。

## 前端设计

### 好友面板（src/overlay/friends.ts）

- `OnlineRow` 增加 `is_friend`；好友行渲染「好友」徽标、**不显示打招呼按钮**（好友操作集中在下方列表，不重复）；陌生人行不变。
- 空态文案「今天还没有人在线」在新语义下自然成立，不改。

### 访客近距离（src/guest/）

- **进场**：`GuestRegistry` 弃用固定槽位；访客从最近屏幕边缘走入，目标点 = 主宠物当前位置旁的偏移位（偏移侧按剩余屏幕空间挑选：右侧优先、不够换左侧；多访客按左/右/远端错开防重叠）。
- **跟随**：`GuestPet` 增加跟随模式——与主宠物距离 > 1.5 倍身位即朝其**当前坐标**追（复用 Behavior 行走），追到偏移距离就停下待机（呼吸/微表情，朝向主宠物）。主宠物照常游走。
- **对话拍**：`GuestDialog` 说话时双方停步、面对面（主宠物 2.5s 回应已有，补朝向设置）。
- **可点击**：
  - 访客身体矩形加入穿透上报（`main.ts` 上报组装点）；访客身体仍**不参与 lock**（点一下即走，无需持续接管）。
  - `pointerdown` 命中访客 = 「摸摸」：本地**先行**反馈——棋盘点阵小桃心粒子（遵守「绝不半透明像素」红线）+ 访客开心微表情 + 反应气泡；随后 fire-and-forget 调 `visitor_interact`（失败只记错误类别日志，不重试不打扰）。
  - 本地按 (uid, 本次到访) 计数，第 4 下起不再上报，访客气泡「摸够啦」。
- **离开**：`main.ts onSocialEvent` 补 `leave` 分支 → 头顶 Banner「XX 的宠物回家了」；访客走出屏幕动画已有（靠空名单 sync 送走的路径保留为兜底）。
- **主宠物出门时送客**：`onAwayChange(away=true)` 除清快闪层外，同步让 `GuestRegistry` 全体 `leave()`（走出屏幕），消除「主人不在家客人还在」。

### 出门方反馈（main.ts）

- 收到 `pet://home-away {away:true, kind:"visit"}`：先播**离场动画**（主宠物走向最近屏幕边缘，约 1.2s，复用 summonTo 行走），到位后再隐藏；同时头顶 Banner「去 XX 家串门啦，8 分钟后回来」。召回/到期回家维持现状瞬现，不加回家动画。
- 收到 `pet://social {type:"visit_rejected"}`：宠物气泡一句「想去找 XX 玩，但扑空了」（短气泡，不打断）。
- 收到 `pet://social {type:"interacted"}`：宠物气泡「在朋友家被摸了 N 下，好开心」（N 取事件 count；同一次串门多条事件按 count 单调去重，只显示最新）。

### 气泡收拢（src/overlay/bubble.ts）

- 简单通知 Banner 默认 `followPet: true`；好友回执卡（`showCard`）同样锚定头顶。
- 宠物隐藏/不在家时自动退回右上角（复用现有 `releaseFromPet`）。
- **锚链防重叠**：定位顺序 = 宠物头 → 主气泡 → Banner/回执卡，沿远离宠物的方向依次纵向排开、间隙 10px（头顶放不下时整体翻到脚下，沿用主气泡现行规则）；抽成纯函数供单测。
- 提醒大卡片（`showReminder`）维持右上角不动。

## 隐私红线核对

- `share.rs` 白名单上报**零改动**；心跳上报结构不变。
- 在线总览只暴露心跳本就公开的字段（`uid/nick/pet_name/state`）+ `is_friend`（只对请求者自己的好友集有意义）；过滤隐身者的语义与现状一致。
- `/visit/interact` 全程鉴权，且只能作用于**自己家**当前访客名单内的对象，无遍历面。
- 事件 payload 白名单构造（`{from, nick, pet_name, count}`），512B 硬上限；Rust 日志只记阶段与错误类别。
- 摸摸为纯本地绘制 + 鉴权上报，无新增感知数据；桃心粒子用棋盘点阵，不产生半透明像素。

## 错误处理

- `/visit/interact` 错误类别：`not_visitor`（TA 不在你家/已离开）、`enough`（摸够啦）、鉴权失败；文案为服务端常量，直传客户端。
- 本地反馈先行、上报 fire-and-forget：单次网络失败最多丢一次亲密度累加，不重试（宁静优先），日志记类别。
- 旧服务端 + 新客户端窗口期：`is_friend` 缺省 false，好友可能带打招呼按钮短暂出现（部署即消，接受）。
- 新服务端 + 旧客户端：字段被忽略，行为同现状，无破坏。

## 范围外（明确不做）

通知队列/排队、摸摸之外的互动动作（喂食/玩具）、好友行的打招呼入口、提醒大卡片收拢、用户手动发起 8 分钟串门、回家动画（召回/到期仍瞬现）、WebSocket 推送、访客之间的互动、桃心之外的花活特效。
