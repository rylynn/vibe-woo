# 设计：Minecraft 风格形态（玩家皮肤 + 动物模型）

- 日期：2026-09-22
- 状态：已与用户逐节确认
- 关联文档：`docs/plans/2026-08-29-vibe-pet-design.md`（4.3/4.4 精灵图预留接口、5.2 性能约束）、`docs/plans/2026-08-29-m1-verification.md`（穿透手工验证清单）

## 1. 背景与目标

宠物现有形象是纯参数化 Canvas 像素画（`src/avatar/` 9 字段 × `src/render/` 五个绘制器，无任何图片素材）。本设计引入第二套形象体系：**Minecraft 风格形态**——体素盒模型 + 贴图渲染，支持：

1. 玩家形态：标准 64×64（含 64×32 旧格式归一化）皮肤 PNG，内置预置 + 用户导入
2. 动物形态：v1 做猫、狗两只，内置模型与贴图，不接受导入
3. 表情与动画：宠物现有情绪引擎（mood 心情、深夜困倦、flow 眯眼、卡住盯屏、眨眼节奏、视线扫动）**全量延续**到 MC 形态脸上
4. 访客串门可见：同步服务扩展皮肤上传/下载，访客侧拉取渲染，失败降级参数形象

物品形态（16×16 平面、无骨架）**不在 v1 范围**，骨架设计预留扩展位。

### 用户已确认的决策

| 决策点 | 结论 |
|---|---|
| 素材来源 | 预置库 + 用户导入皮肤 PNG 都要 |
| v1 形态范围 | 玩家 + 猫/狗；物品后续 |
| 表情机制 | 情绪引擎全量延续（程序化眼部覆盖），不做换脸贴图 |
| 访客同步 | v1 就要支持访客看到 MC 形象 |
| 渲染方案 | A：实时 2.5D 体素渲染（否决预烘焙精灵图/手绘精灵） |
| 性能验收 | CPU 空闲 <1% 红线不变，上线前后都要实测，超标走帧缓存兜底 |

## 2. 架构

### 2.1 形象体系扩展（前后端契约）

`PetAvatar` 变为判别联合：

```ts
type PetAvatar =
  | { kind: 'parametric'; /* 现有 9 字段原样 */ }
  | { kind: 'minecraft'; form: 'player' | 'cat' | 'dog'; skinId: string }
```

- Rust `AvatarConfig`（`src-tauri/src/config.rs`）同步加 `kind` 与对应字段，serde 用 tag 区分；**无 `kind` 字段的旧配置反序列化为 parametric**，平滑兼容。
- 配置只存引用（form + skinId）；皮肤文件本身存 app data `skins/` 目录，索引由 Rust 维护。
- 前后端手工对齐规则（CLAUDE.md 前后端契约）继续适用，改一处同步另一处。
- 前端分流处未识别的 kind 一律回退 parametric 默认渲染，不崩溃。
- 已知限制（接受）：minecraft 配置不含 parametric 9 字段，回滚到旧版本应用时反序列化会失败、形象重置为未领养——与现有任何配置结构演进的回滚行为一致，不做额外兼容层。

### 2.2 新增 `src/mc/` 模块（与 `src/render/` 平级）

| 文件 | 职责 |
|---|---|
| `model.ts` | 盒骨架定义类型（盒子尺寸 w/h/d、UV 原点、关节 pivot、层级父节点）+ 玩家/猫/狗内置模型常量。玩家用 MC 标准模型：头 8×8×8、躯干 8×12×4、双臂双腿 4×12×4，标准 64×64 皮肤 UV；猫/狗用自定义简化 UV + 内置贴图 |
| `skin.ts` | 皮肤加载与校验（PNG 魔数、64×64 或 64×32、≤64KB）、归一化（64×32→64×64：补透明区、左腿由右腿镜像生成）、alpha 二值化（阈值 50%）、tint 重映射贴图生成（离屏 canvas，档位切换才重生成） |
| `pose.ts` | 纯函数：`Motion + t + EyeFrame + Appearance → 量化姿态`。所有自由度量化成档：头 yaw 8 档（[-45°,+45°]）、头 pitch 3 档、四肢摆动相位 8 档、呼吸 3 档、squash 档复用现有公式 |
| `project.ts` | 纯函数：姿态 → 面多边形列表（固定正交轴测投影 + painter's 深度排序）。视角全应用唯一、参数写死：身体恒定正面微右偏 + 俯角（2:1 类 MC 等距观感） |
| `render.ts` | 面列表 → `drawImage` 序列：`setTransform` 整数量化剪切、`imageSmoothingEnabled=false`、顶点 `Math.round`；每帧可见面 drawImage 上限 30 次 |

**接入点**：`drawAvatarFigure()`（现三处共用：主宠物/选择器预览/访客）按 `avatar.kind` 分流。parametric 路径零改动；mc 路径产出同等地位的绘制序列。`pet.ts draw()` 末端的脏矩形/指纹结构不动，只扩指纹字段。

### 2.3 像素完美约束（红线 3 的落实）

- 投影矩阵系数全整数化；所有多边形顶点整数对齐。
- 皮肤透明区（帽子/外套 overlay 层）加载时 alpha 二值化，运行时**零半透明像素**。
- tint（focused 提亮 +0.09 / dim 降饱和 ×0.35 亮度 ×0.6，参数与现有 `applyTint` 一致）不用叠色——`skin.ts` 按档位在像素色阶上直接预生成重映射贴图，绘制路径无任何 alpha 操作。
- 整数倍缩放沿用 `BASE_CELL=48 × SIZE_STEPS [1,2,3,4]`，MC 形态整体高度对齐到同一档位体系。

### 2.4 视角与移动

- 身体恒定正面视角，**不渲染背面**；左右移动用水平镜像（scaleX −1）+ 走路动画表达，避免多方向骨骼组合爆炸。
- 头部自由转向叠加在固定身体视角上，是视线/张望/盯屏情绪的载体。

## 3. 动画与表情

### 3.1 Motion → 体素动画（`behavior.ts` 不动，消费端换实现）

| Motion | 体素表现 |
|---|---|
| idle | 呼吸浮沉（3 档）+ 偶尔小动作 |
| walk | 四肢摆动（8 相位）+ 上下弹跳 + 移动方向镜像翻转 |
| hop | 跳跃高度曲线 + 落地挤压（squash 作用于盒子高度） |
| lookaround | 头部 yaw 扫过 8 档（复用现有 SACCADE 节奏） |
| stretch | 双臂上举 + 身体拉伸 |
| held | 拖拽悬垂，四肢下垂微摆 |
| sleep | 模型绕 x 轴 90° 躺倒 + 闭眼 + 2fps 慢呼吸 |

### 3.2 表情：情绪引擎 → 脸部覆盖

- `MicroExpression` 引擎原样复用，`EyeFrame{shape,lid,gazeX,gazeY}` 灌进 mc 渲染。
- **眼部覆盖**：在头部正面 8×8 贴图区域的 MC 规范眼位（固定两行）上，用程序化眼型（现有 8 种形状逻辑搬到 8×8 网格）替换皮肤自带眼部。不做皮肤内容检测——固定位置，确定可测；非标准画风皮肤同样处理。
- **视线**：gaze 偏移 → 眼睛绘制偏移 + 头部微 yaw（映射到 8 档），实现「头跟着看」。
- 困倦黑眼圈 / flow 眯眼 / mood 眼型随 EyeFrame 走，零新情绪逻辑。

### 3.3 帧指纹扩展（性能关键）

`frameVisualKey()`（pet.ts）追加 mc 维度：`(form, skinId, tint 档, mirrored, motion, limbPhase, headYawStep, headPitchStep, breathStep, squashStep, eyeKey)`（本地皮肤以 skinId 标识内容；sha256 hash 只用于同步协议）。姿态全量化 → 有限姿态集，画面不变时零绘制，跳帧机制对体素路径完全生效。

## 4. 素材与设置

### 4.1 内置资产

- 玩家皮肤 4-6 张：自绘或 CC0，许可证记录在资产目录 README；预归一化后随前端打包。
- 猫/狗：模型常量（`model.ts`）+ 自定义 UV 贴图（前端资产），不接受导入（MC 原版 entity 贴图格式复杂且动物与玩家皮肤 UV 不兼容——UI 上讲清楚「皮肤仅对玩家形态生效」）。

### 4.2 导入管线（文件操作全在 Rust）

新命令：
- `mc_import_skin(path)`：校验（PNG 魔数、尺寸、大小）→ 归一化拷贝到 `skins/{id}.png` → 登记索引 → 返回 skinId；校验失败只回错误类别，不透传内部细节
- `mc_list_skins()`：内置 + 已导入清单（含缩略图数据）
- `mc_delete_skin(id)`：删文件与索引；内置皮肤不可删；若删除的是当前使用中的皮肤，配置回退默认参数形象并提示

### 4.3 设置 UI

- 设置面板「形象」区新增「Minecraft 形态」入口：形态选择（玩家/猫/狗）→ 皮肤库网格（内置 + 导入）→ 预览（与主渲染同一 `drawAvatarFigure` 分流，所见即所得）。
- 首次领养流程不动，MC 形态只从设置进。

## 5. 访客同步（同步服务扩展）

### 5.1 协议

- 账号资料新增 `mc: { form, skinHash } | null`，随现有白名单构造上报（`share.rs` 从零构造原则不变；皮肤是用户主动选择的外观，不含任何感知数据）。
- 新端点（业务逻辑收口在共用的 `worker-edgeone/edge-functions/api/lib-account.js`，两套部署各放薄存储适配层，不复制业务逻辑）：
  - `PUT /api/skin`：登录态；仅 64×64 PNG ≤64KB；按内容 sha256 寻址存储；限流
  - `GET /api/skin/:hash`：返回皮肤字节，长缓存头；hash 即完整性校验
- 皮肤仅数 KB，Cloudflare KV / EdgeOne KV 均可容纳，不引入 R2。

### 5.2 访客侧流程

串门事件携带 `mc` 字段 → 本地缓存（app data，hash 寻址可永久缓存）查 skinHash → 未命中 `GET /api/skin/:hash` → 喂给 mc 渲染。**失败降级**参数默认形象；带指数退避，不做重试风暴。`guest-pet.ts` 走同一 `drawAvatarFigure` 分流，自动获得渲染能力。

## 6. 性能（硬验收）

- CPU 空闲 <1% 红线不变；**上线前后均需实测**（活动监视器观察睡眠/待机/活跃三档），验收步骤写入 `docs/plans/` 手工验证清单。
- 保障手段：
  1. 姿态全量化进指纹——画面不变零绘制；
  2. 每帧 drawImage 典型 ≤24、最坏 36（全套 overlay；空 overlay 按像素跳过）；
  3. 分层帧率沿用（睡眠 2 / 待机 8 / 活跃 30 fps，`effectiveActivity` 提档逻辑不动）；
  4. tint 贴图预生成，不在帧路径做像素级色阶重映射。
- **兜底后手**：实测超标时给 `render.ts` 加「姿态+皮肤 → 缓存位图」帧缓存层（等价退化为预烘焙方案），上层不动。

| 手工清单 | CPU 三档实测；窗口穿透 M1 回归（动了 draw 路径必过）；视觉截图验收（固定姿态出图对比） |

## 8. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 渲染器复杂度（最大风险） | 实施第一步是 PoC：玩家模型静态站立出图，像素完美约束在此验证，不过关立即回到方案讨论 |
| WebKit 亚像素采样行为差异 | 整数变换 + smoothing off，PoC 阶段验证 |
| CPU 超标 | 帧缓存兜底层（见 §6） |
| 内置皮肤版权 | 自绘或 CC0，许可证随资产记录 |
| 动物动画调校工作量 | 每只动物独立 pose 参数表；v1 仅猫/狗 |

## 9. 里程碑（每段可独立合入，各自定版本号）

1. **M1 渲染 PoC**：`model/skin/project/render` 最小闭环，静态玩家站立 + 内置皮肤，探针测试，像素完美验证。前端 `PetAvatar` 判别联合类型在此引入，配临时验证入口（仅开发期硬切，不持久化）
2. **M2 动画+表情**：Motion 全映射、眼部覆盖、指纹扩展、CPU 实测达标
3. **M3 素材+设置**：皮肤导入管线、皮肤库 UI、猫/狗模型、完整前后端配置契约（Rust `AvatarConfig` 扩展 + 设置持久化在此合入；M1/M2 期间不落盘）
4. **M4 访客同步**：上传下载端点、访客拉取降级、`test:remote` 验收

版本语义：纯功能加法、配置向后兼容，按 **minor** 提；具体版本号在每次合入前与用户确认（遵循版本合入规则）。

## 10. 明确不做（v1）

- 物品形态（16×16 平面）
- 动物形态导入皮肤
- MC 原版 entity 贴图格式兼容
- 皮肤编辑器
- 多方向身体朝向渲染（只有正面 + 镜像）
- 背面视角 / 相机自由旋转
